# 结算画面设计文档（参考 P1）

定稿日期：2026-11-13。参考图 P1 学的是结构与克制，不抄皮。通用令牌（颜色/字体/字号阶梯/间距）沿用《UI 最终方案》（ui-final-plan-2026-11-12.md），本文只写本屏特有部分。

**最重要的一句：这一屏不需要新数据系统。** 结算所需的全部数据已经存在——`ACoopCqbGameState::Report`（`FMissionReport`，已复制同步）里有计数、分组分值、总分、满分和评级字符串，`bDebriefOpen` 就是这一屏的开关。本屏是纯表现层。

## 一、参考拆解（P1 为什么成立）

- 纯黑场，全屏只有一个焦点：中央评级圆。其余信息全部退到边缘（左下明细、右上时间、底部按钮）。
- 明细不是表格，是“账单”：分组标题 + 逐项 + 右对齐分值，读起来像收据，信息密但不吵。
- 红色只出现两次：左上标题下的短线、总分下的一行小注记。全屏唯一的情绪色，极其克制。
- 按钮分置底部两端：离开类在左（退出/设置），继续类在右（重试/返回总部），符合“左退右进”的阅读习惯。

## 二、布局（1920×1080 画布，安全边距 左/右 48、上/下 40）

| 元素 | 位置/尺寸 | 内容 |
|---|---|---|
| 任务名块 | 左上，x=48, y=40 | 任务名 28px（如「锈蚀车间」）；其下 2px 红短线，宽 64；再下小标 13px「行动结算 / AFTER ACTION」 |
| 评级圆 | 屏幕中心，Ø 560 | 2px 圆环 + 中央评级字母（见 §三） |
| 总分 | 圆正下方居中，距圆 24 | 总分数字 40px；其下一行小注记 13px（见 §三） |
| 明细区 | 左下，x=48，宽 560，底边距 120（避开按钮行） | 分组账单（见 §四），行高 26，组间空 16 |
| 时间块 | 右上，x 右对齐至 1872, y=40 | 「时刻」小标 13px + 用时 28px（如 41:13.01）；其下「个人最佳」小标 + 时间 16px 次级色 |
| 按钮行 | 底部 y=1000，高 40 | 左组：退出至主菜单、更改任务设置；右组：重试、返回总部。按钮为无边框文字按钮，hover 时文字变主色+左侧 2px 红线 |

## 三、评级圆与总分

- **评级字母**：直接取 `Report.Grade`（已是字符串），字号 300px，Barlow Condensed。默认用主文本色 `#EDEEF0`；**仅 S 级**时可用暗金——这是全项目“金色是否保留一个 accent”未决项在本屏的落点：本屏默认关，想开只开这一处。
- **圆环即进度**：圆环不是完整圆，弧线长度 = `Score / MaximumScore`，从顶部顺时针生长，缺口留在右下——和 P1 的断环构图一致，同时是一张无声的得分率图。
- **总分注记行**（P1 里是红字“模组已删除：非官方分数”的位置）：放本局最值得说的一句，优先级：① 有惩罚时显示惩罚原因（如「击杀已投降者 −×××」，红色）；② 否则若隐藏任务有完成，显示「隐藏记录已达成 ×N」；③ 否则不显示。

## 四、明细账单（字段级映射，全部来自 FMissionReport）

分组与行（左列小计数 `完成/总数` 13px 次级色，中列名称 16px，右列分值 16px 右对齐）：

| 组 | 行 | 计数来源 | 分值来源 |
|---|---|---|---|
| 任务目标 | 主目标（文案取 ObjectiveDescriptions，如「找到账本」「查封工作台」逐条） | bPrimaryComplete 及各目标完成态 | PrimaryPoints |
| 次要目标 | 标记/查封类目标（如三台工作台若走标记计数） | MarkedCompleted / MarkedTotal | MarkedPoints |
| 嫌疑人 | 已控制嫌疑人 | Arrested / SuspectsTotal | ArrestedPoints |
| | 已击毙嫌疑人 | Neutralized / SuspectsTotal | NeutralizedPoints |
| 平民 | 已解救平民 | Rescued / HostagesTotal | HostagePoints |
| | 平民死亡（仅 >0 时出现，红色计数） | HostagesLost | 计入 Penalties 展示 |
| 小队 | 无警员阵亡（全员生还时为 1/1） | Survivors / OperatorsTotal | SurvivalPoints |
| 隐藏记录 | 隐藏任务（组名在结算才揭晓，见下） | HiddenCompleted / 隐藏总数 | HiddenPoints |
| 惩罚 | 惩罚合计（仅 <0 时出现，整行红色） | — | −Penalties |

隐藏记录的呈现规则（这是本项目和参考图拉开差异的一笔）：局内隐藏任务不在面板显示，**结算时才揭晓**——已完成的逐条列名打勾；未完成的只显示一行灰字「未达成的隐藏记录 ×N」，不公布内容，留给玩家下一局自己发现。注意数据：`Report` 只有 HiddenCompleted 计数，条目名需从任务配置的隐藏目标列表按完成标记取（MissionFlow 侧补一个完成名单即可，不需要新系统）。

## 五、呈现时序（进场动画，总长约 2.2 秒，可跳过）

1. 黑场淡入 200ms，任务名与时间块先就位。
2. 明细逐行出现：每行 120ms 间隔，分值从 0 滚动到实际值（count-up 300ms）。
3. 圆环弧线按得分率生长 600ms，评级字母随后淡入+轻微放大落定（1.06→1.0，200ms）。
4. 按钮行最后淡入。任意键/点击：跳过剩余动画直接到终态。
5. 失败结算（bOperatorsWon=false）：跳过第 3 步的“生长”，圆环只画到实际得分率，字母位置改显 Grade（失败评级由计分规则给，如 F），任务名下红线保留，主目标未完成行计数变红。

## 六、联机规则

- 全队同屏、同一份 Report（已复制），各自客户端同时打开（bDebriefOpen）。
- 按钮权限沿用项目既有的房主权威模式：**重试 / 返回总部只有房主可点**，队员侧置灰并带 13px 提示「等待房主决定」；退出至主菜单人人可点（只退自己）。
- 房主点击后全队同步执行（重试 = 重新 Travel 本图；返回总部 = Travel 回 Lvl_Range）。
- 用时取服务器任务计时；「个人最佳」是本地数据：按任务 ID 存进 ShooterGameUserSettings 或独立 SaveGame（**这是本屏唯一需要新增的小数据**，一个 Map<任务ID, 最佳时间+最高分> 足够），无记录时显示 --:--.--。

## 七、落地顺序

1. UMG 骨架：按 §二 摆位，假数据跑通时序动画。
2. 绑 Report 与 ObjectiveDescriptions，PIE 单人验证数字与游戏内实际一致。
3. 隐藏记录条目名接 MissionFlow 完成名单。
4. 房主权限与全队同步（重试/返回总部）。
5. 个人最佳存档读写。
6. 失败结算分支验证。
